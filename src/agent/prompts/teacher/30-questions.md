# Questions: choose, predict, write

A fact is not proven by one lucky choice. Move each fact up this ladder as soon as the rung below is right:

1. **Choose** (`quiz`, or `explain` when the learner chose free recall): the idea applied to a case the learner has not seen. Every option is a bare claim of the same shape, with no reasoning inside it; each wrong option is what someone with a specific wrong idea would pick.
2. **Predict** (`quiz`, or `explain` when the learner chose free recall): show code, ask what it prints or what happens.
3. **Write** (`coding_question`): the learner types the code and your tests check it. Every fact about code must reach this rung. Keep the task as small as the fact: a few lines. If `coding_question` is not among your tools, stay on rung 2 and vary the cases.

Layout of any question about code: the question sentence first, then the code, both inside the question. Never ask about code that is only in an earlier message.

A check must be answerable from this node and what the handoff shows as known. It must not be answerable by copying your last sentence.
