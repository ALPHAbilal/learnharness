# Programming learning: workspaces, build courses, and Infinite mode

Status: approved by the owner on 2026-11-11 and built. See "As built" at the end for the calls made during the build.

## Intent

Make LearnHarness specialise in computer science and programming, so a learner
gets good at programming by building real things, at their own level, and
understands why each piece works instead of memorising it.

The model is CodeCrafters ("build your own X" in stages, in your own editor),
with two differences: the course is generated by the agent for any topic the
learner names, and it is fitted to what the learner already understands.

## The three parts

```
 1. WORKSPACE     every chat gets a folder on disk; agent has full access
 2. BUILD COURSE  teacher plans a project in stages (teaching sessions)
 3. INFINITE      third kind of chat: agreed target, endless harder challenges
```

Part 1 is the foundation. Parts 2 and 3 depend on it and are independent of
each other.

## Part 1: workspace per chat

Decided by the owner:

- The learner sets one main workspace folder, as a path on their own disk, in
  Settings.
- Every chat gets its own folder under that main folder, created automatically.
- The learner writes and runs code in their real VS Code, opened on that folder.
  No editor or terminal is built into the app.
- The agent has full access: it reads the files and runs commands on its own,
  without asking each time.
- Every tool call the agent makes is saved to a log, exactly as it was made.
- The agent may create and change files anywhere on the disk, not only inside
  the chat's folder ("all for now"; may be narrowed later).
- The workspace path is required: a new chat cannot be started until the main
  workspace folder is set.
- Only new chats get a folder. Chats that already exist are left as they are,
  with no migration.

Accepted risk, stated plainly: commands run with the learner's own user
permissions and no sandbox. The log shows what happened afterwards. It does not
prevent a bad command.

Current state of the code that this builds on:

- Agent file tools today are read-only: `read`, `ls`, `find`, `grep`
  (`src/agent/tools/`). There is no write tool and no command tool.
- A sensitive-path guard already refuses private locations and `.env` files
  (`src/agent/tools/fs-shared.ts`). It stays in force.
- Settings already has a file-access section with a folder list
  (`src/core/file-access.ts`). The workspace path is a new, separate setting.
- The coding-questions plugin has a code runner that works in a temporary
  folder (`plugins/coding-questions/src/runner.ts`). It is prior art for
  timeouts and output limits, and is left as it is.
- Chats are stored one JSON file per chat under `PATHS.chats` (`config.ts`).

What has to be added:

- A workspace-path setting, and its field in the Settings screen.
- Folder creation when a chat is created.
- An "Open in VS Code" control on the chat.
- New agent tools: run a command (starting in the chat's folder), and write a
  file (any path the sensitive-path guard allows).
- A block on starting a new chat while the workspace path is unset, with a way
  to set it from there.
- A tool-call log per chat.
- The chat's folder path given to the agent, so it knows where to look.

## Part 2: build course (teaching sessions)

Decided by the owner:

- The agent generates the course for the topic the learner names.
- The course is fitted to the learner's level and taught from first principles.
- A stage ends when the agent has checked the work in the folder and the learner
  has answered one "why does this work" question. Then the next stage opens.

How it fits the existing agents (builder's call, see below): no new agent. The
prober still measures first. The teacher gets one new prompt fragment in
`src/agent/prompts/teacher/` that says, for programming topics:

- the plan is a project cut into stages, each stage a small working step;
- each stage starts with why the piece is needed, before how to write it;
- the learner writes the code, the agent never writes the solution for them;
- the agent checks a stage by reading and running the code in the folder.

The existing plan (`plan_init`, a validated dependency map) carries the stages.

## Part 3: Infinite (a third kind of chat)

Decided by the owner:

- It is its own kind of chat with its own button, next to Teaching and
  Practice. Its name is "Infinite".
- Practice stays exactly as it is today.
- It has a defined process.
- It starts with a conversation in which learner and agent agree on the
  ultimate target.
- The agent then attacks that target from every useful angle and depth.
- It mixes in other topics only when they add value to that target.
- Each solved challenge is followed by a harder one, with no end.
- Challenges are solved in the chat's folder in VS Code, not in an in-app
  editor.

How it fits (writer's call): Infinite gets its own prompt directory,
`src/agent/prompts/infinite/`, composed like practice (own base, curated shared
appendix). It reuses the existing `problem` and `conclude` tools, which already
give one challenge at a time with a pause between them, plus the workspace
tools from Part 1.

Current state: the session kind is `"teaching" | "practice"` across the code
(for example `src/core/ports.ts` `createChat`, `src/core/plugins.ts`,
`src/core/plugin-shortcuts.ts`, `src/core/compaction.ts`). Adding a third kind
touches the new-chat screen, chat storage, agent selection, prompt composition
and its Settings list, and the plugin API types.

## Goals

- A learner can name a programming topic and be building it in VS Code, in
  stages sized to them, within one session.
- The agent verifies work by running it, not by trusting a paste.
- Infinite never runs out and stays on the agreed target.

## Non-goals

- No editor, terminal, or embedded VS Code inside the app.
- No sandbox or container for running code.
- No hand-written course catalogue.
- No change to the knowledge graph.
- No change to the existing coding-questions plugin.

## Anti-goals

- The agent writing the learner's solution for them.
- Stages that can be passed without understanding why the code works.
- An Infinite chat that drifts into topics unrelated to the agreed target.
- Copying CodeCrafters' course text, names, or branding.

## Constraints

- `AGENTS.md`: no design guessing; plan approved before implementation.
- `AGENTS.md`: this Next.js version has breaking changes; read
  `node_modules/next/dist/docs/` before writing code.
- Layering: the agent layer never imports the store adapters
  (`src/agent/prompt-segments.ts` header).
- Prompt fragments follow `src/agent/prompts/README.md`: numeric prefix, kept
  concise, tool names must match the real schemas.
- Practice composes only an allowlist of shared fragments.

## Calls made by the writer (not the owner)

1. Build courses reuse the prober and teacher; one new teacher prompt fragment.
2. Infinite reuses the practice tools (`problem`, `conclude`) under its own
   prompts, instead of getting new challenge tools.
3. The sensitive-path guard keeps applying to the new tools.
4. Commands get a timeout and an output size limit, as the plugin runner does.
5. The log is one append-only file per chat, stored with the app's data.

## As built

Calls made by the builder during implementation, beyond the ones listed above:

1. The workspace tools go to the teacher, practice and infinite agents. The
   prober does not get them: it only measures.
2. Practice sessions gain the two tools and the folder note because every chat
   has a folder; their own instructions are untouched.
3. `run_command` removes the app's own provider keys from the command's
   environment, so a learner's program or an `env` call cannot print them.
4. `write_file` honours the existing protected-location guard and the learner's
   own file-access restriction; the workspace folder is always allowed.
5. `LH_WORKSPACE_DIR` overrides the setting, for scripted runs and tests.
6. Plugins are told an Infinite chat is a practice chat, so the plugin API still
   has two session kinds.
7. Every `run_command` and `write_file` call shows in the chat as a collapsed
   card with the command or path, next to the per-chat log file.
8. The folder is named `<title-slug>-<id-tail>`; the "VS Code" control sits in
   the chat's top bar and shows the folder path when the editor cannot start.
